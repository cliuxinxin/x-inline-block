# X 行内拉黑 Chrome 扩展设计

## 目标

开发一个 Manifest V3 Chrome 扩展，在 X/Twitter 的帖子作者名后显示红色小字“拉黑”。用户单击后，扩展立即通过 X 原生界面完成拉黑及确认，不显示插件自己的确认框。

## 范围

- 支持 `https://x.com/*` 与 `https://twitter.com/*`。
- 覆盖首页时间线、搜索结果、评论区和用户主页中的帖子。
- 不处理右侧关注推荐、广告和当前登录用户自己的帖子。
- 不调用 X 私有 API，不读取、保存或传输登录凭据。
- 扩展没有后台服务，所有逻辑均在页面内执行。

## 交互

- 按钮紧跟帖子作者的显示名称，文案为“拉黑”，采用低干扰红色小字样式。
- 点击后按钮立即变为“处理中…”，并禁止重复点击。
- 扩展打开该帖子的原生“更多”菜单，选择“拉黑 @用户名”，再点击原生确认按钮。
- 成功后显示“已拉黑”；X 随后可按自身行为移除相关帖子。
- 若找不到菜单项、确认按钮或操作超时，按钮恢复为“拉黑”，并通过按钮标题提示失败；不执行模糊匹配到的其他危险操作。

## 架构

扩展由内容脚本、样式表和静态清单组成。内容脚本使用 `MutationObserver` 扫描动态插入的 `article[data-testid="tweet"]`，为每个帖子定位作者区域并注入一次按钮。点击处理器只在当前帖子范围内寻找原生更多按钮，再在 X 打开的可见菜单和对话框中按稳定的 `data-testid` 与可校验的拉黑语义选择目标。

为了便于测试，DOM 定位、用户名解析、帖子资格判断、状态更新和原生流程编排拆成可导出的纯函数或依赖注入函数；浏览器中则以普通内容脚本方式自动启动。使用 Node 内置测试运行器和轻量 DOM 测试环境进行回归测试，不引入构建步骤。

## 安全与失败处理

- 只有用户明确单击行内按钮后才会触发拉黑流程。
- 每次操作绑定到被点击的帖子，避免误用其他帖子的菜单按钮。
- 菜单项必须同时满足 X 拉黑相关测试标识或明确文案校验；无法确认时立即失败。
- 任一步骤设定短超时，失败后清理状态，不无限轮询。
- MutationObserver 批量调度扫描，避免时间线更新时反复遍历造成卡顿。

## 验证

- 自动化测试覆盖：按钮注入及去重、广告和自身帖子排除、动态帖子注入、点击状态、成功流程、找不到菜单项时安全失败。
- 静态验证 Manifest V3 清单、所需文件和匹配域名。
- 在本地 Chromium 中加载解压扩展，确认扩展可启动；真实拉黑行为需要用户已登录 X 的页面进行最终验收。
